# 验收：交付前按顺序做

规则写得再多，也不如出片后逐项检查。下面每一项都要做；**发现的问题一轮修完**，修完再查一遍。修复中又冒出的小问题（音量、某一帧）算同一轮；更大的问题交付时用一句话告诉用户。

## 1. 脚本检查（必须全部通过）

```sh
node <skill>/scripts/check.mjs <工程>                 # 字体、品牌色、事实
cd "$LIB" && node core/render/readcheck.mjs <工程>    # 每段要读的字停留够不够
```

| 检查 | 不通过时 |
|---|---|
| 字体 | MG 文字改用 `var(--ly-…)`；属于产品界面的，给它的容器加 `data-layer="product"`；字体没加载上就检查 `brand/fonts/` |
| 品牌色 | 换成品牌色；确实需要的（产品自己的状态色等）写进工程根目录的 `palette-extra.json` 并写明理由，例如 `{"#2F6BD8": "Laiye Worker 浅色主题的进行中色，MG 跟随产品"}` |
| 事实 | 有出处的补进 FACTS.md；戏剧化的写进"戏剧化处理"；动画中间值用"忽略正则"声明；没有出处的从画面上删掉 |
| readcheck | 延长停留，或减少字数；不要让字提前消失 |

偏小的字只提醒，不判失败，但要逐条看：要读的字必须推大，装饰性的小字可以留。

## 2. 看片

```sh
sh <skill>/scripts/review.sh <工程> 1      # 每秒一帧，拼成联系表，外加末帧
```

至少看两遍联系表，对照这张清单：

- [ ] 对照已审批的故事线：每一段的"关掉声音能读到"在画面上成立；段落顺序和关键信息没有走样
- [ ] 每一帧只有一个视觉重心
- [ ] 每个段落边界都有东西承接，没有"换页"
- [ ] 主体够大（关键时刻至少占画面高度的三分之一），不贴边
- [ ] 文字不压在要看的元素上；字没被裁切
- [ ] 同一时刻只有一样东西是来也黄；浅色底上没有黄字
- [ ] 没有第三方 logo、真实邮箱和人名
- [ ] 删除线落到屏幕上 ≥ 8px；箭头 ≥ 50px（放不下就改用进度条或顺序点亮）
- [ ] 转场里没有空白帧
- [ ] 末帧是定版（logo 停住），不是淡出

关键动作（点击、落定、甩镜、核验打勾）用 0.2 s 帧条再看一遍：`node core/render/still.mjs <工程> --range a:b:0.2`。

## 3. 听和看成片

- **关掉声音看一遍**：不靠字幕和声音，能看懂产品做了什么吗？看不懂就是画面没讲清楚。
- **带声音全速看一遍**：每个看得见的动作有没有声音；两处安静在不在；音乐有没有盖住关键拟音。
- 响度：`build.sh` 最后打印的应在 −14 LUFS 左右，峰值不超过 −1 dBFS。
- 黑帧：`ffmpeg -i <成片>.mp4 -vf blackdetect=d=0.1 -an -f null - 2>&1 | grep black_start`，除非故意，不应有输出。

## 4. 交付

工程文件夹里要有：

- `<片名>.mp4`（30 fps，约 −14 LUFS）和 `poster.jpg`（最有代表性的一帧，文字完全落定的时候：`node core/render/still.mjs <工程> <t> --prefix po_ --out <工程>/out` 后改名）
- `<片名>.srt`（有旁白或字幕时）
- `BRIEF.md`、`FACTS.md`、`故事线.md`（已审批版本）、`TREATMENT.md`、`CREDITS`
- 源码和一条命令就能重建的 `build.sh`

告诉用户：成片和工程在哪里；一句话说清创作角度；检查结果（通过了什么、有什么已知的小问题）；`CREDITS` 里列了用到的字体和素材。然后问用户的修改意见。
