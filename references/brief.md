# 简报：用最少的来回拿到能写 TREATMENT 的全部信息

做一条产品片，时间大头花在"理解目标、找素材、整理背景"上。这一步按固定顺序做，**先自己挖素材，再一次性问用户**。

## 1. 先自己盘点（不问用户）

成片质量主要取决于上下文是否充分。最好的输入是：真实录屏或截图（产品长什么样）、产品资料和数据（讲什么）、品牌规范（长什么样），以及用户自己的分镜或故事线（怎么讲）。2026-09 的 Revor AI 产品片没用任何 skill，靠一份逐镜分镜加录屏和官网品牌规范，效果就很好。这一步的目的就是把这些尽快凑齐。

用户给的文件夹、文档、录屏，你自己先读完：

| 素材 | 怎么读 | 读出什么 |
|---|---|---|
| 推广策划、需求文档（.md / 飞书文档） | 直接读 | 目的、受众、渠道、核心句、时长、参考片 |
| 录屏 | `sh scripts/recsheet.sh <录屏> 8 <输出目录>` 出联系表，逐张看；找到关键状态后 `ffmpeg -ss <秒> -i <录屏> -frames:v 1 -q:v 3 <名字>.jpg` 截全尺寸帧再细看 | 界面状态、按钮和选项的原文、数据、流程顺序 |
| 截图 | 直接看 | 同上 |
| 数据表、PDF、邮件附件 | xlsx / pdf skill | 单号、金额、字段名 |
| 产品卡 | `brand/products/<产品>/card.md` | 名称写法、能说什么、界面结构、取色 |
| 之前做过的同产品片子 | 它的 TREATMENT.md、FACTS.md | 已核实的事实、用户提过的意见 |

边读边写 `FACTS.md`：**原文照抄，写明出处（文件 + 时间点或页码）**。录屏里 AI 员工说的数字是产品的输出，不等于事实：凡是要上画面的数字，都和原始单据（PDF、表格）交叉核对；对不上的标"待确认"，放进故事线的"需要你拍板"。录屏里的真实邮箱、人名、账号记到"替换掉的隐私数据"一节，片中换成虚构的。

## 2. 起草 BRIEF.md

按 `templates/BRIEF.md` 填。读得出来的直接填；读不出来但有合理默认的，填默认值并标"（默认）"：

| 项 | 默认 |
|---|---|
| 时长 | 社媒 Highlight 30–60 s；功能演示 45–90 s；活动开场 15–30 s |
| 画幅 | 1920×1080；视频号、抖音竖版 1080×1920 |
| 声音 | 只有音乐和音效，不配旁白；画面要不靠字幕也能看懂 |
| 语言 | 用户写简报用的语言；海外渠道用英文 |
| 风格 | 要演示真实产品操作 → Laiye Screencast；讲能力、概念、数字、发布预告 → Laiye Keynote |
| 帧率 | 30 fps；要剪进 25p 工程就 25 fps |
| 故事线审批 | 要（用户明确说"不用审，直接做完"才跳过） |
| 分镜审核 | 不需要 |

另外三项一定要写出来，它们决定故事线怎么讲（`references/storyline.md`）：

- **看完以后**：观众知道什么、相信什么、去做什么。
- **观众已知**：看之前他们知道什么（知道 AP 是什么？听说过 Laiye 吗？）。
- **误读风险**：第一次看的人可能误会什么。

## 3. 一轮提问

用 `AskUserQuestion`，**一次问完，最多 4 个问题**，每个问题给推荐项。只问素材里查不到、你又不该替用户决定的事：

- 片子要让人记住的那一句话，以及看完以后观众该去做什么（素材里没有时）
- 有没有必须出现、或绝对不能出现的东西（客户名、数字、功能）
- 要不要旁白（影响时长和结构）
- 风格拿不准时：两种风格各一句话说明差别

不用问"要不要审故事线"：默认要审，用户主动说不用时才跳过。

不要问：素材里写着的东西、品牌规范里定好的东西（颜色、字体、logo）、你作为导演该决定的东西（结构、镜头、配乐）。

**没有产品的录屏或截图，就先找用户要**：模型只有看到产品的样子，才知道该画什么；这一步不能跳过。素材不够时，提一个具体的要求，不要让用户列镜头清单："请打开 Laiye Worker，从 Marketplace 添加 X，配置到第一次运行完成，全程录屏"或"每一步截一张图"。

## 4. 开工

把回答原文贴进 BRIEF.md 的"用户补充"，用 3–5 行向用户复述简报（做什么、给谁、多长、什么风格、关键事实），然后直接写故事线，不再追问。之后唯一的停顿点是故事线审批（`references/storyline.md`）；其他小问题按导演判断处理，写进 TREATMENT。
