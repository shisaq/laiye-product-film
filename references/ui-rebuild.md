# 重绘产品界面

Laiye Screencast 的画面是重画出来的产品界面，不是录屏。重绘比录屏更可控：镜头推到 3 倍也清晰；每个字都是数据，换语言只换一张字符串表；没有隐私泄露；不用等真实运行。代价是要和真界面逐个状态对照。

## 1. 参考帧

- 录屏：`sh scripts/recsheet.sh <录屏> 8 <目录>` 出联系表，找到片子要用的每个状态，再截全尺寸帧：`ffmpeg -ss <秒> -i <录屏> -frames:v 1 -q:v 3 ref/<状态>.jpg`。
- Laiye Worker 已有的参考帧和取色：`brand/products/laiye-worker/`（`card.md` 有界面结构图，`ui-tokens.json` 有浅色和深色两套颜色）。
- 列一张**状态清单**：片子里出现的每个界面状态（默认、弹窗打开、选项选中、清单走到第几步、结果出来），每个状态对应一张参考帧。只重绘这些状态。

## 2. 搭界面

- **按参考帧自己的像素尺寸布局**（Laiye Worker 录屏是 1828×1080），元素按量到的位置摆放；整个界面作为一个窗口放进世界里，再由镜头决定怎么看。
- **所有文字放进一张表** `STR[lang]`，从第一行代码就这样做；界面文案按录屏原文抄（同时写进 FACTS.md）。
- **状态 → HTML 是纯函数**：`app(state)` 每帧根据 t 算出状态，再生成 HTML。不在帧之间保留任何状态。
- **产品界面的根元素加 `data-layer="product"`**：检查脚本据此区分产品界面层和 MG 层（产品层按产品自己的颜色和字体，MG 层按品牌规范）。
- **镜头和 MG 要对准的元素加 `data-a="key"`**：高亮框、标注、连线端点、光标目标都从 DOM 量，不手填坐标。
- CSS 类名加一个统一前缀（如 `.lw-`），避免和 MG 层的类名撞车。
- 颜色从参考帧取：`$LIB/.venv/bin/python -I scripts/sample_colors.py ref/x.jpg 120,340 800,212`（取点）或 `… ref/x.jpg --top 12`（最常见的颜色）。
- 字体：英文界面用 Inter，中文界面用思源黑体，替代产品的系统字体。
- 图标用内联 SVG 线性图标，按参考帧的大小和线宽画；不贴截图。

## 3. 对照

每个状态渲染一帧，和参考帧并排看：

```sh
cd "$LIB" && node core/render/still.mjs <工程> <t> --q cam1 --prefix cmp_ --out <工程>/cmp
.venv/bin/python core/render/sheet.py <工程>/cmp/vs.jpg <参考帧>.jpg <工程>/cmp/cmp_<t>.jpg --cols 2 --w 960
```

`--q cam1` 让镜头固定在 1× 全景（起步工程的 main.js 支持）。一个状态一个状态过，直到剩下的差异都是故意的（简化、隐私替换）。

## 4. 简化和替换

- **第三方系统**（Gmail、Google Sheets、Xero……）画成简化界面：保留观众认得出的结构（收件箱列表、表格网格、账单表单），名字放在中性色块上，**不用对方 logo**。
- **隐私**：真实邮箱、人名、账号、组织 ID 换成虚构的（`ap.team@yourco.com`），写进 FACTS.md 的"替换掉的隐私数据"。
- **省略**：授权页、加载等待、无关的会话和卡片可以省；写进 FACTS.md 的"省略和简化"。
- **不加产品没有的东西**：按钮、模式名、动效都以录屏为准。MG 层可以加标注，但产品界面层不能编。

## 5. 让它能读

- 屏幕上的字号 = 界面 CSS 字号 × 界面缩放 × 镜头缩放。录屏原始 17px 的正文，在 1× 全景里只有 17px，读不了；被"点名"的那一行要推到 ≥ 26px（缩放约 1.6 倍以上）。
- 一个窗口要被读时，占画面宽度 70–80%。
- 每个操作一个特写（选项 → 提交 → 结果），镜头跟着光标在它们之间移动；全景只用在"关系本身就是重点"的时候。
- 中文界面的行宽比英文窄：同样的版式，中文版按实际文字宽度排，不要沿用英文版量出来的位置。
