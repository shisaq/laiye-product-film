# Laiye Keynote · 来也暗场发布

基于 Lemo-Opuscar（MIT）的 Dark Tech Keynote（dark-keynote）改写，改动见 [CHANGES.md](CHANGES.md)。
来也的既有规范来自 HyperFrames 项目 `20260811 APA 企业版宣传视频 MG` 和 `20260923 智单通` 的 frame.md。

> 发布会级别的产品片：近黑舞台、细网格、柔光，只有一个强调色——来也黄。**主角是产品本身**：重绘的真实界面被从窗口里拿出来，放到舞台上当特写（Marketplace 卡片、AI 员工的对话、选项卡、清单、生成的结果），带着网格般的精确移动。
> 参考（只学语法）：Apple 发布会（黑舞台、光扫、一屏一句、单独一屏的大数字）；Linear / Stripe / Vercel 发布片（吸附网格的运动、1px 线、一个强调色）；Steve Reich 的过程音乐（相位、减法）。不用它们的名字、界面、字体、旋律、logo。

## 1. 本质，以及它不是什么

讲**来也产品**的发布级短片。这是产品 MG：观众要看到产品长什么样、人怎么和它交互、它做出了什么，所以**主角是重绘的真实产品界面**（来自用户给的录屏或截图），只是不放在一段连续的桌面录屏里，而是一块一块拿到暗场上做特写：AI 员工的头像和对话、一张选项卡、一条执行清单、一份结果。抽象元素（文档卡、数字、连线）只用来讲界面讲不清的概念和做过渡。它活在暗场上，柔和的光照着它，**来也黄只给最重要的那个元素**。

适合：新品或新能力发布、30–60 秒的产品短片、活动开场；以及以概念为主的片子（APA 四大支柱、报告与奖项），这类片子里产品界面可以少，但仍然要出现。

风格靠**精确**定义：每个元素吸附网格，每个动作落在拍子上，每个声音属于一个设计好的家族。戏剧性来自对比：先是生成出来的混乱界面，然后一个果断动作，然后是留白。

它和 Laiye Screencast 的区别在舞台和镜头：Screencast 是桌面上一段连续的录屏感，Keynote 把界面拿出来放在暗场上做特写、配大字。两者展示的都是产品，一条片子里也可以混用（例如从桌面开场，再把关键界面拿到舞台上）。它不是：纯文字快闪（用 laiye-flash-video）；不是全息 HUD（没有扫描线）；不是只有抽象动效、看不到产品的概念动画（2026-10-26 Mega Showcase 开场片 v1 的教训）。

## 2. 材质与渲染

- **舞台**：近黑底 `#0B0B0C`，上方中部轻微提亮，偏离中心一团低透明度（个位数百分比）的暖白光，四角 50–55% 暗角。48px 模块的细网格（白 ~3%，每第 4 条 ~6%）。不加颗粒。
- **产品界面按录屏重绘**（`references/ui-rebuild.md`），从窗口里拿出来单独放在舞台上：一张卡、一段对话、一条清单，比例放大到能读。产品界面保留产品自己的样子（浅色界面就是浅色卡片浮在暗场上），MG 和大字用品牌规范。
- **辅助的抽象元素代码绘制**：文档卡、带等宽文件名的文件图标、列表行、标签、徽章、进度条。不画红黄绿按钮、菜单栏、Dock。
- **表面**：三级抬升的深色表面（`#17171A` / `#202024` / 更亮一级），1px 边（~8% 白），1px 顶部内高光，柔和阴影。
- **对象身份连续**：同一个东西（如"可执行流程文档"）在全片用同一个组件、同样的比例和末帧状态，换场景时它变身份，不换外观。
- **景深**：2.5D 镜头（`s = 1/(1/zoom − z)`），靠近镜头的卡片随放大变糊。转动用分条透视（rotY ≤ ~24°）。
- **光是揭示工具**：只有光扫过的像素才亮起，没被照到的地方停在几个百分点的亮度。

## 3. 色彩逻辑

- **中性阶只用中性或略暖的灰**（`#0B0B0C` → `#17171A` → `#202024` → `#2A2A2E` 线 → `#8A8A8F` 次要字 → `#F5F5F0` 主文字）。**不要偏蓝的冷灰**，它会把黄衬脏。
- **唯一强调色：来也黄 `#FFE600`**，带自己的光晕。只留给产品是什么、做了什么：主角元素、关键动作、确认、关键数字、CTA。如果两样东西都是黄的，有一样错了。黄底上的字用 `#0B0B0C`。
- **问题色**（`#FF4D3D`）只在问题存在时出现；转折之后再不出现。问题色 = 噪声，黄 = 产品。
- **通过色**（`#3DDC84`）只用于"校验通过 / 自动直通"，面积小。
- 次级色只作运动中的**类别编码**（每种数据一条轨迹），从品牌延伸色板取（蓝色系、卡其、橙）并降低饱和度，不放在静态界面上。不用紫、粉、霓虹。

## 4. 字体与字幕

- 中文标题、大数字：雅酷黑（`--ly-display-zh`），64–200px，紧字距。英文标题：TT Supermolot Neue（`--ly-display-en`），600 / 700。
- 正文、标签、说明：思源黑体 / Inter（`--ly-sans-*`），24–44px。
- 单号、配置编码、状态文字：JetBrains Mono（`--ly-mono`），开等宽数字，小型大写标签加宽字距。
- 标题一屏一句。大数字独占一屏，上面**不压字幕**：数字就是信息。
- **辅助文字必须带来新信息**（原因、状态、证据），不能和主标题说同一件事。
- **字幕是界面组件**：底部居中的 toast（深色半透明胶囊、1px 亮边、柔和阴影、约 40px），0.16 s 轻升淡入；停留 ≥ max(1.8 s, 台词 + 0.6 s)。光标在画面里打出的字不再重复做字幕（只进 `.srt`）。
- 中文片画面文案统一用中文，只保留 APA、ADP、AI、RPA 这类必要缩写；不加英文副题和英文装饰字。

## 5. 运动质感

- 30 fps 逐帧（交付进 25p 剪辑时用 25 fps），不跳帧：这是精确，不是手工感。
- **一切落在网格上、落在拍子上**。动作提前一拍开始，在拍子上落定。缓动是快出 + 一次小过冲（`back`，s ≤ 1.3）并立刻停稳。不要漂浮的正弦漂移，不要反复弹跳。
- **出生要短、按类型统一**（落下、甩入、滑入、弹出，0.2–0.3 s），同一类元素用同一种动作。紧张感可以用几个像素的颤动。
- **飞行**走曲线，沿末端切线过冲；同类元素朝同一方向弯，不交叉。
- **消失要设计**（一拍收回一部分、CRT 关机式压成一点），不简单淡出。
- 短标题卡：快、干脆、无拖尾；长镜：生长、收拢、展开、归位。
- 舞台和网格自己不动，只有镜头带着它们动。

## 6. 镜头语法

一套词汇，不是固定路线。开场和结尾从题目里来。

| 运镜 | 表达 | 适合 |
|---|---|---|
| 锁定的极近特写，对准一个小元素 | 亲密，屏幕上一个东西活着 | 一个动作；一个状态 |
| 按小节在对数空间里持续拉远 | 积累，规模从一点长出来 | 流程越来越多；网络扩张 |
| 穿过定格画面推近 | 时间停住，注意力收窄 | 一个决定；发现问题的那一刻 |
| 一拍内甩出拉远 | 因果同时看见 | 同步完成；部署落到各处 |
| 钻进一个小元素（对数缩放）+ 匹配剪辑 | 进入细节 | 一个关键计数；一行日志 |
| 半秒插入从源头展开 | 过载 | 通知风暴；报错；选择过多 |
| 近乎锁定，物体转动、光扫过 | 展示，产品是主角 | 揭示；新版本；功能名 |
| 横向慢移过一个界面平面 | 眼睛按顺序读 | 时间线；流水线 |
| 俯视网格平面图 | 系统视角 | 架构；权限；流程图 |
| 回到之前的构图 | 押韵：什么变了 | 前后对比；闭环 |

构图：大量留白，一个焦点，黄色在焦点上。荷兰角和晃动只用于混乱段。
**转场 = 界面展开 / 收拢**：每次换镜都是一个界面元素展开成全画面，或全画面收进一个元素；或者来也黄色块横扫（0.6 s）作为章节切换。不淡入淡出，不留空白帧。

## 7. 声音

- **调音打击乐和 pad**：马林巴、颤音琴、钢片琴、合成 pad 或持续音、低频正弦脉冲、沙锤、合成拨弦、毡锤钢琴。干净、干、极简。也可以用全合成科技感配乐。
- **音乐是看得见的过程**：相位、逐小节加一个音、逐步减音直到剩一个、细分拍子来加速而不改速度，或者所有东西落在同一个和弦上。
- **两种声音家族 = 故事**：混乱的声音是**分散的**（失谐几十音分、随机声像、每个来源音色不同）；产品的声音是**一个家族**（毡锤轻敲、玻璃轻碰，同一调式，居中），很多次落定合成一片和谐的微光。
- 拟音：光标轻响、矮键盘、通知玻璃声、文件落下、窗口 whoosh、堆叠闷响、按下时毡锤 + 正弦下坠、光扫微光、数字颗粒、CRT 关机。
- 无声是工具：画面停住时所有轨道归零；无声之后的第一个声音最重要。J / L 切让声音跨过界面转场。
- 混音：旁白下音乐压 ~8 dB、拟音压 ~4 dB；−14 LUFS；不加颗粒。旁白：自信克制，短陈述句。

## 8. 本风格的招牌手法

按需选用：

- **生成出来的堆积**：按规则生成界面元素，越来越快，成百上千——混乱不是画出来的，是生成的。适合：待处理单据堆积、手工对账的工作量。
- **吸附网格**：一拍之内所有东西飞进网格，承诺一次说完；网格在此之前不可见。适合：一次配置覆盖所有渠道、审计全部变绿。
- **活的元素**：光标或产品最小的活元素是主角和品牌标志。
- **定格**：所有东西停在半空，声音归零。适合：拦下一张异常单；发送前的那一秒。
- **光扫揭示**：一条柔和的光带扫过，只有被照到的像素亮起（前沿柔和，高光 ≤ 20%，≤ ~1.3 s）。
- **数字从字形噪声里锁定**：数字乱跳，按十六分音符逐位锁定，带一点回弹。
- **类型流**：元素沿彩色曲线飞到各自的行，类别读起来像一条条流。适合：单据分拣、日志分级。
- **收起**：界面一拍拆一件，直到只剩一个元素。
- **黄色横扫换章**：来也黄色块自右向左扫过全画面，章节标题落在黄底上（黑字）。
- **同一份文档换身份**：同一个文档组件依次被登记、授权、调用、验证，外观不变、角色在变。

## 9. 常见坑

- 冷蓝灰的中性色把来也黄衬脏 → 用中性或略暖的灰。
- 两样东西都是黄的 → 只留一个。
- 霓虹、玻璃拟态、镜头光晕、粒子堆砌、3D 金属反光 → 品牌禁用。
- 退化成一屏一屏的文字页（像 PPT）→ 每拍从上一拍长出来，说清楚是什么东西跨过了这条边界。
- 辅助文字重复标题 → 删掉或换成新信息。
- 连线没有连着真实节点、不讲一件事 → 删掉。
- 半透明画布做分条透视会出现竖缝 → 先投影不透明的表面，再在屏幕空间打光。
- 高光太硬像贴纸反光 → 前沿柔和，高光 ≤ 20%。
- 网格里元素太少留下空洞，看起来像错误 → 按规则生成，再按每组槽位数裁剪或补齐。
- 用一个纯色矩形表示"关闭"像占位符 → 压扁真实的表面。

## 10. 引擎

起步工程：`templates/starter/`（DOM 版，带 2D 镜头和锚点），说明见 `references/engine.md`。要用光扫揭示、2.5D 透视、数字乱跳这类技术时，**写完 TREATMENT 之后**取 opuscar 的示例源码学技术：`sh "$LIB/plugin/skills/lemo-opuscar/scripts/setup.sh" demo dark-keynote`，看 `$LIB/styles/dark-keynote/demo/engine.js`。只借技术，不借故事和镜头。

## 11. 变化空间

主角、问题画面、结构、开场、结尾、镜头路线和配乐的过程都由题目决定：

- 结构：**倒计时**（发布清单逐项打勾，每项一个界面瞬间，结束在"已上线"）；**并排**（旧流程和新流程分屏同跑，旧的被淹没，新的提前做完）；**缩放阶梯**（一个像素 → 一个组件 → 一屏 → 整个企业，每一级一个新事实）。
- 开场：**先给数字**（黑底上一个大数字，倒着揭示它的意思）；**空网格的俯视图**一格格被填满；**第一帧就是插入风暴**，平静之后才来。
- 结尾：**只剩一格**亮着来也黄；**产品安静运行**的远景，不加字；**已上线状态**（一条确认 toast，然后定版 logo）。
