# Laiye Screencast · 来也实机录屏感

基于 Lemo-Opuscar（MIT）的 Living Screencast（living-screencast）改写，改动见 [CHANGES.md](CHANGES.md)。
参考片：AP Highlight v03（`examples/ap-highlight-v03/`）。

> 看起来像来也产品的真实录屏，其实每个窗口、按钮、消息都是用代码重画的。AI 员工在后台做的事，由盖在界面上的 MG 层演出来。
> 参考（只学语法）：Screen Studio 式录屏（跟随光标的自动推拉、平滑光标、点击推近、窗口浮在壁纸上）；Apple Guided Tour（真实界面，一句话一个功能）；Linear / Raycast 浅色发布片（一拍一个功能，用留白做节奏）。不要用它们的界面、音乐或镜头。

一条产品演示，通常 30–60 秒。简报给产品和要讲的事；故事、镜头、编排、声音由你定。

## 1. 本质，以及它不是什么

画面像**来也产品的真实录屏**，但不是录屏。所有窗口、菜单、消息、按钮都用 HTML/CSS/SVG **重画**，所以镜头能推到任何位置，任何缩放下文字都清晰，每个字都可控，录屏里的隐私数据可以换掉。

**AI 员工的工作靠 MG 层演出来**，不靠角色：附件飞出来变成单据卡，扫描线读过它，类型标签落下；比对卡把三张单据的数字并排对齐；台账里一行行写进去；结论用一圈高亮框和一句标注点明。

**两个行动者**：光标是用户；AI 员工可以用它自己的头像标记当向导（对话顶部那个"头像 + 名字"的胶囊）。它从 Marketplace 卡片上诞生，停在对话顶部，干活时走到正在处理的地方（邮箱、清单、会计系统），做完停在等你决定的地方。它不表演、不卡通，只是让观众一直知道"它现在在哪、在做什么"，替代原风格里吉祥物的叙事作用。不出现手，不出现会表演的吉祥物。

它不是：暗场发布片（那是 Laiye Keynote：同样是真实窗口，但没有桌面，放在近黑舞台上、章节交界出大字）；不是真实录屏（不用截图）；不是卡通。

## 2. 材质与渲染

- **真界面，重画**：每个标签、选项、按钮的文字都和录屏原文一致（写在 `FACTS.md` 里）；不用截图，不写假文案。演示数据前后一致，来自产品真实输出。
- **产品界面按产品自己的主题画**（`brand/products/<产品>/ui-tokens.json`），浅色就是浅色，深色就是深色。
- **第三方系统**（Gmail、Google Sheets、Xero……）也按录屏重绘：布局、字段、按钮、配色照录屏，可以省略无关部分，加简化的浏览器框；只是不用对方 logo 图片，名称用文字（`brand/BRAND.md` §4）。
- **桌面**：应用窗口浮在壁纸上，带柔和阴影。缩放始终 ≥ 1，镜头不拉出屏幕外。壁纸和时钟可以承担时间流逝。
- **MG 层**：白色或近黑卡片，1px 细边，柔和阴影，圆角 8–18px，品牌字体。凡是挂在界面元素上的 MG（高亮框、标注、连线端点），位置**每帧从 DOM 量**，不手填坐标。
- **景深只为注意力服务**：压暗或暗角其余部分；要读的字永远不糊。
- **运动模糊**只在甩镜时出现，由镜头速度算出，加在未变换的外层容器上。

## 3. 色彩逻辑

- **产品界面层**：严格按产品原色。
- **MG 层**：中性卡片打底，**同一时刻只有一种状态色**：进行中 = 产品自己的进行色（Laiye Worker 浅色主题是 `#2F6BD8`）；通过 = 绿（`#2FA55A` 浅底 / `#3DDC84` 深底）；异常 = 红（`#D9483B` / `#FF4D3D`），只在异常存在时出现。
- **来也黄**留给品牌时刻：Laiye Worker 图标、关键动作的强调、片尾 logo 横条和 CTA。在浅色界面上黄色**只做色块、横条、荧光笔底，不做字色**。
- **类别色**（几种单据、几条数据流）只从品牌延伸色板取：蓝色系、卡其、橙。**不用紫色和粉色**（品牌规范禁用）。
- 主题切换可以是故事事件：日夜、亮暗，整部片的状态跟着变。

## 4. 字体与字幕

- 产品界面层的字体跟产品走：英文界面用 Inter，中文界面用思源黑体（替代系统字体）。
- MG 层用品牌字体：标题和标签用 `--ly-display-en` / `--ly-display-zh`；一行说明用 `--ly-sans-*`；单号、金额用 `--ly-mono`。
- **默认没有底部字幕条、章节标签、加速标签**（2026-10-23 用户意见）。文字只以**标注**出现：在特写处，紧挨着它说的元素（不压在元素上），一句短话（英文 ≤ 8 词，中文 ≤ 14 字）。**关掉声音、没有字幕，片子也要看得懂。**
- 一句全片主张（如 "Set up once."）可以单独占一屏：画面压暗，居中大字，品牌标题字体。
- 有旁白时才加字幕：底部居中的磨砂胶囊，停留 ≥ max(1.8 s, 台词时长 + 0.6 s)，同时导出 `.srt`。
- 片名尽量"长在界面里"：Marketplace 卡片的标题、通知、窗口标题。

## 5. 运动质感

- 30 fps。界面按真实产品的方式动（它自己的弹窗、清单打勾、打字）；不给产品加它没有的花哨动效。
- **因果可见**：每个 MG 反应都由画面上看得见的事件引起（一次点击、一封邮件到达、一步打勾）。
- **承接**：新的 MG 元素从画面上已有的东西里长出来（附件变成单据卡，清单一步展开成一个工作台，表格一行变成台账记录）。段落交界处不凭空出现新东西。
- MG 入场短（0.25–0.5 s），缓出；只有图章、徽标可以带一点回弹。退场要设计：收回来源、折叠、移出画面，不在画面中间淡没。
- **光标**：平滑的弧线路径，点击时缩到 0.82 约 0.1 s，带一圈扩散环；屏幕上的大小恒定（系统光标的 1.5 倍）；不瞬移。
- 时间流逝用时钟、壁纸、步数计数器表现，默认不打"▶▶ 6×"标签。

## 6. 镜头语法

录屏软件式的镜头：在屏幕里一镜到底，缩放 ≥ 1；只有换地方（另一个应用或窗口）时才换镜，用甩镜或界面展开完成。

| 运镜 | 表达 | 适合 |
|---|---|---|
| 推近到光标或输入点 | "事情在这里发生" | 选一个选项；点 Add；输入 |
| 静止时的轻微漂移 | 应用是活的 | 等结果；读一段回复 |
| 甩镜（带模糊） | 这里是因，那里是果 | 提交 → 另一个系统里出现结果 |
| 推近 + 压暗定格 | 记住这一个承诺 | "Draft only"；"Approval stays with you" |
| 跟随清单或对话往下走 | AI 员工逐项推进 | 六步清单；连续的配置卡 |
| 拉回整窗 | 全貌 | 总结；前后对比 |
| 推向结果 | 证据 | 台账新行；会计系统里的草稿 |

**一次只有一个视觉重心**（2026-10-23 用户意见）：新的重心进来时，上一个要压暗、折叠或离开画面。除非"对比"本身就是要讲的事，否则不分屏。
**可读性是算术**：屏幕上的字号 = CSS 字号 × 界面缩放 × 镜头缩放。镜头"点名"的字落到屏幕上 ≥ 26px。一个要被读的窗口应占画面宽度的 70–80%。

## 7. 声音

- 默认：全合成的科技感配乐（2026-10-23 用户意见）。四四拍电子鼓、sub bass、16 分音符 pluck 琶音、侧链 pad、FM 铃音、上升音效和重音，110–124 BPM。
- 拟音：触控板点击、卡片弹出、清单打勾、通知提示音、扫描声、图章落下的闷响；只在甩镜时用 whoosh。
- 关键承诺之前留一段近乎无声；无声之后的第一个声音是全片最重要的声音之一。
- 有旁白时音乐压低约 10 dB，音效避开字的起音，响度 −14 LUFS。

## 8. 本风格的招牌手法

按需选用：

- **配一次，处处生效**：每答完一题，就有一枚标签飞进汇总面板（Gmail · Sheets · Xero · 1%），最后一行亮起 "Setup complete"。
- **附件变单据**：邮件附件飞出来变成小单据卡，扫描线读过，类型标签落下，三张配成一组。
- **并排核验卡**：三张单据的关键数字并排逐行对齐，一致就打勾，不一致的那一格变红。
- **时间换景**：时钟飞转、壁纸由暮到夜再到晨，AI 员工一直在干活。
- **聚光确认**：其余全部压暗，一圈高亮框套住承载承诺的那个元素（Draft、Approve）。
- **写回系统**：甩到第三方窗口，记录一行行写进去，再回读校验。
- **光标停在决定上**：光标落在人才该点的按钮上（Approve），但不点。
- **长在界面里的片名**：Marketplace 卡片标题、系统通知就是片名。

## 9. 常见坑

- 编造功能或改名 → 每个按钮、选项、模式名都对照 `FACTS.md` 和录屏；录屏里没有的，片子里也没有。
- 同时有好几个视觉重心、分屏 → 一次一个（v02 → v03 的主要修改）。
- 字太小 → 按第 6 节的算术推近。
- 手填坐标的 MG 在镜头一动之后就离开了界面 → 每帧从 DOM 量。
- 第三方 logo、录屏里的真实邮箱和人名 → 名字放在中性色块上，数据换成虚构的。
- 浅色界面上的黄字；紫色类别色 → 品牌规范禁止。
- 吉祥物表演 → B2B 片太卡通（2026-10-23 用户意见）。
- 字幕条、章节标签、加速标签把画面塞满 → 默认不要。
- 配置被误读成"每封邮件都要手动设置" → 把配置演成开头的一次性步骤，之后再也不出现。
- 结尾淡出 → 定版停住，硬切结束。

## 10. 引擎

起步工程：`templates/starter/`，说明见 `references/engine.md`。参考实现：`examples/ap-highlight-v03/` 的 `main.js`（DOM 锚点、镜头、运动模糊、MG 叠层）、`film.js`（时间线：关键时刻、镜头关键帧、光标、事件）、`ui.js`（状态 → HTML 的界面重绘）、`sound.py`（合成配乐和拟音）。**写完 TREATMENT 之后**才看它，只借技术，不借结构。

## 11. 变化空间

故事、结构、开场、结尾、镜头路线、配乐每次都重新决定，离参考片越远越好：

- 结构：**配一次，然后它值夜班**（v03 用过）；**先看结果**（开场就是会计系统里的草稿，倒回去讲它怎么来的）；**跟着一张异常单**（只讲被拦下的那张发票）；**一天的数字**（早晨打开电脑，昨夜的工作量在一张卡上滚出来）；**POV**（"你雇了一位 AI 员工"的第一人称视角）。
- 开场：一条系统通知；Marketplace 里点 Add；进行到一半的任务；直接给结果。
- 结尾：产品图标 + 一句主张 + CTA + 来也 logo；光标停在人做的决定上；夜色再次降临，它还在值班。
